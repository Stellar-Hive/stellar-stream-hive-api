# Integration Guide

This page is for anyone building against Stellar Stream Hive programmatically
&mdash; a bot, a dashboard, a payroll tool, or your own frontend. There are two
ways in: the [indexer API](/docs/api/overview) (fast, simple, eventually
consistent within one poll interval) or the contracts directly (authoritative,
requires a Soroban RPC endpoint and more setup). Most integrations should
start with the API and only reach for direct contract calls when they need to
*write* (create/withdraw/cancel), since the API is read-only by design.

## Querying the API

A minimal typed client for the four read endpoints:

```typescript
interface StreamView {
  id: string;
  sender: string;
  recipient: string;
  token: string;
  total_amount: string;
  withdrawn: string;
  start_ledger: number;
  end_ledger: number;
  cliff_ledger: number;
  cancellable: boolean;
  status: "pending" | "active" | "completed" | "cancelled";
  created_at: number;
  streamed_amount: string;
  withdrawable_amount: string;
  progress_percent: number;
}

interface Stats {
  total_streams: number;
  active_streams: number;
  total_streamed: string;
  total_withdrawn: string;
}

// cliff_ledger == start_ledger means "no cliff" -- tokens vest from ledger 1.
// Only treat it as a real cliff when cliff_ledger > start_ledger.
const hasCliff = (s: StreamView): boolean => s.cliff_ledger > s.start_ledger;

class StreamHiveClient {
  constructor(private baseUrl: string) {}

  private async get<T>(path: string): Promise<T> {
    const res = await fetch(`${this.baseUrl}${path}`);
    if (!res.ok) {
      const body = await res.json().catch(() => ({}));
      throw new Error(`${res.status} ${body.error ?? "unknown_error"}: ${body.message ?? res.statusText}`);
    }
    return res.json() as Promise<T>;
  }

  listStreams(): Promise<StreamView[]> {
    return this.get("/streams");
  }

  getStream(id: string): Promise<StreamView> {
    return this.get(`/streams/${encodeURIComponent(id)}`);
  }

  getStreamsBySender(address: string): Promise<StreamView[]> {
    return this.get(`/senders/${encodeURIComponent(address)}`);
  }

  getStreamsByRecipient(address: string): Promise<StreamView[]> {
    return this.get(`/recipients/${encodeURIComponent(address)}`);
  }

  getStats(): Promise<Stats> {
    return this.get("/stats");
  }
}

const client = new StreamHiveClient("http://localhost:8080");
const myStreams = await client.getStreamsByRecipient("GABC...XYZ");
```

### Fetching every page

List endpoints are paginated with `limit` and `offset` query parameters and
report the total number of matching rows in the `X-Total-Count` response
header. A common need is "all streams for an address", which means walking
every page. This helper follows `X-Total-Count` with `limit=200`, increasing
`offset` until every item has been collected, and throws on a non-OK response
using the same error shape as the `get` helper above:

```typescript
async function fetchAll<T>(path: string): Promise<T[]> {
  const limit = 200;
  const items: T[] = [];
  let offset = 0;

  while (true) {
    const separator = path.includes("?") ? "&" : "?";
    const res = await fetch(`${client["baseUrl"]}${path}${separator}limit=${limit}&offset=${offset}`);
    if (!res.ok) {
      const body = await res.json().catch(() => ({}));
      throw new Error(`${res.status} ${body.error ?? "unknown_error"}: ${body.message ?? res.statusText}`);
    }

    const page = (await res.json()) as T[];
    items.push(...page);

    const totalHeader = res.headers.get("X-Total-Count");
    const total = totalHeader === null ? null : Number(totalHeader);
    offset += page.length;

    // Stop when the server reports we've seen everything, or when a short
    // page tells us there is nothing left to fetch.
    if (page.length < limit) break;
    if (total !== null && offset >= total) break;
  }

  return items;
}

// Example: every stream paying a given recipient, across all pages.
const allForRecipient = await fetchAll<StreamView>(
  `/recipients/${encodeURIComponent("GABC...XYZ")}`,
);
```

<CalloutBox variant="info" title="Reading X-Total-Count in the browser">
  Browsers only expose a response header to JavaScript if the server lists it
  in `Access-Control-Expose-Headers`. The API already sets
  `Access-Control-Expose-Headers: X-Total-Count`, so `res.headers.get("X-Total-Count")`
  works from a browser origin. If you proxy the API through your own backend,
  make sure that proxy forwards the header too.
</CalloutBox>

<CalloutBox variant="warning" title="Don't do arithmetic on these fields as numbers">
  Every amount field above is typed `string`, not `number`, on purpose --
  see [API Overview: response conventions](/docs/api/overview#response-conventions).
  `Number("30000000000")` loses precision above 2<sup>53</sup>; always parse
  with `BigInt` before doing any arithmetic, as in the next section.
</CalloutBox>

## Python example

The same rule applies in Python: parse the string amounts with `int()`, never
`float()`. This sums `withdrawable_amount` across every stream paid to one
recipient, following the `X-Total-Count` header so it doesn't stop at the
default page size:

```python
import requests

BASE_URL = "http://localhost:8080"


def total_withdrawable(recipient: str) -> int:
    total, offset = 0, 0
    while True:
        res = requests.get(
            f"{BASE_URL}/recipients/{recipient}",
            params={"limit": 200, "offset": offset},
            timeout=10,
        )
        res.raise_for_status()
        page = res.json()
        total += sum(int(stream["withdrawable_amount"]) for stream in page)
        offset += len(page)
        if not page or offset >= int(res.headers["X-Total-Count"]):
            return total


print(total_withdrawable("GDEF...UVW"))  # total in stroops
```

## Rust example

The same read in Rust, using `reqwest` and `serde`. The amounts deserialize as
`String` and are parsed into `i128`, which is the same representation the API
uses on the wire. This reads the first page of a recipient's streams (the
default page size is 50):

```toml
[dependencies]
reqwest = { version = "0.12", features = ["json"] }
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
```

```rust
use serde::Deserialize;

#[derive(Deserialize)]
struct StreamView {
    id: String,
    status: String,
    // Amounts are i128 values serialized as strings, so parse them explicitly.
    withdrawable_amount: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let streams: Vec<StreamView> = reqwest::get("http://localhost:8080/recipients/GDEF...UVW")
        .await?
        .error_for_status()?
        .json()
        .await?;

    let mut total: i128 = 0;
    for stream in &streams {
        println!(
            "stream {} ({}): {}",
            stream.id, stream.status, stream.withdrawable_amount
        );
        total += stream.withdrawable_amount.parse::<i128>()?;
    }
    println!("total withdrawable (stroops): {total}");
    Ok(())
}
```

## Computing `streamed_amount` client-side

You don't have to trust the API's (or the contract's) computed
`streamed_amount` blindly -- it's a pure function of five values that are all
public: `total_amount`, `start_ledger`, `end_ledger`, `cliff_ledger`, and the
current ledger. Here is the exact formula from
[Streaming Math](/docs/concepts/streaming-math), in TypeScript using `BigInt`
to match the contract's `i128` semantics precisely:

```typescript
/**
 * Mirrors api/src/streaming_math.rs::streamed_amount exactly, including the
 * multiply-before-divide ordering and every edge case. All amount/ledger
 * inputs are BigInt to avoid precision loss -- see the "why multiply before
 * divide" section of the streaming-math docs for why order matters here.
 */
function streamedAmount(
  totalAmount: bigint,
  startLedger: bigint,
  endLedger: bigint,
  cliffLedger: bigint,
  currentLedger: bigint,
): bigint {
  if (currentLedger <= startLedger) return 0n;
  if (currentLedger >= endLedger) return totalAmount;
  if (currentLedger < cliffLedger) return 0n;

  const elapsed = currentLedger - startLedger;
  const duration = endLedger - startLedger;
  return (totalAmount * elapsed) / duration;
}
```

To get the current ledger, call `GET /ready` and read its `latest_ledger`
field. The same response also reports `synced`, `contract_configured`, and
`indexed_streams`, so it doubles as a health check. If you'd rather not depend
on the API for this value, you can fetch the latest ledger from Horizon or call
`getLatestLedger` on the Soroban RPC server directly -- both are authoritative
and give you the same ledger sequence number.
