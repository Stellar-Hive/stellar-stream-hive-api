# Registry Contract

The Registry contract maintains an on-chain index of every stream and
platform-wide aggregate statistics. It exists so that "list all streams" or
"what's the platform's total volume" can be answered by a single contract
call, without an off-chain indexer walking every `create` event from
genesis. The Stream contract does not call the Registry: the Registry is
optional and is populated today by a separate caller (for example an off-chain
service) invoking `register_stream` and `update_stream` after the corresponding
Stream events. `stellar-stream-hive-api`'s own `/stats` endpoint mirrors the shape
of `get_stats` (computed independently from indexed events, as a
cross-check) -- see [API Reference: Stats](/docs/api/stats).

Source: [`stellar-stream-hive-contract`](https://github.com/Stellar-Hive/stellar-stream-hive-contract)
(contract module `registry`). For testnet and mainnet deployment addresses, see
[`DEPLOYMENTS.md`](https://github.com/Stellar-Hive/stellar-stream-hive-contract/blob/main/DEPLOYMENTS.md)
in the contract repository.

## Types

### `RegistryStats`

```rust
pub struct RegistryStats {
    pub total_streams: u64,
    pub active_streams: u64,
    pub total_streamed: i128,
    pub total_withdrawn: i128,
}
```

| Field | Meaning |
|---|---|
| `total_streams` | Count of every stream ever created, regardless of current status. |
| `active_streams` | Count of streams whose last-recorded status is `Active`. `Pending` does not count. |
| `total_streamed` | Lifetime cumulative sum of every stream's committed `amount` at registration. It only ever goes up and is not live accrual. |
| `total_withdrawn` | Sum of `withdrawn` across every stream. |

### `RegistryError`

```rust
pub enum RegistryError {
    AlreadyInitialized = 1,
    NotInitialized = 2,
    InvalidAmount = 3,      // an amount argument was negative
    AlreadyRegistered = 4,  // stream_id was already registered
    StreamNotFound = 5,
    MathOverflow = 6,       // checked arithmetic overflowed or underflowed
}
```

## Functions

### `initialize`

```rust
pub fn initialize(env: Env, admin: Address)
```

One-time setup. Records the `admin` address and initializes `RegistryStats`
to all zeros.

- **Auth:** `admin.require_auth()`.
- **Errors:** `AlreadyInitialized`.

### `register_stream`

```rust
pub fn register_stream(
    env: Env,
    stream_id: u64,
    sender: Address,
    recipient: Address,
    token: Address,
    amount: i128,
)
```

Records a newly created stream. It is called by the separate caller that
populates the Registry (see the introduction), not by the Stream contract. The stream is
recorded with status `Active`. It increments `total_streams`,
`active_streams` and `total_streamed` (by `amount`), and emits a `register`
event.

- **Auth:** none; the function takes no caller parameter.
- **Errors:** `AlreadyRegistered` if `stream_id` was already registered,
  `InvalidAmount` if `amount` is negative, `MathOverflow`.

### `update_stream`

```rust
pub fn update_stream(env: Env, stream_id: u64, withdrawn: i128, status: StreamStatus)
```

The populating caller is expected to call this after every `withdraw`,
`withdraw_max`, and `cancel_stream` on the Stream contract. `withdrawn`
is the stream's **absolute** withdrawn total, not a delta. The Registry
computes the delta against the previously recorded value internally and adds
a positive delta to `total_withdrawn`. A `withdrawn` value below the recorded
one is stored but does not reduce `total_withdrawn`. It then stores the new
`withdrawn` and `status`.

`active_streams` changes only when the status moves into or out of `Active`:
a transition into `Active` increments it, a transition out of `Active`
(for example to a cancelled or completed status) decrements it, and any other
update leaves it unchanged.

- **Auth:** none; the function takes no caller parameter.
- **Errors:** `StreamNotFound`, `InvalidAmount` if `withdrawn` is negative,
  `MathOverflow`.

### `get_all_streams`

```rust
pub fn get_all_streams(env: Env) -> Vec<u64>
```

Returns every stream id ever registered, oldest first. Intended for small
deployments and tooling; for platform-scale queries prefer
[`GET /streams`](/docs/api/streams) on the indexer API, which paginates and
avoids loading the full on-chain vector into a transaction's execution budget.
On-chain, prefer `get_streams_page` over `get_all_streams` for large registries.

- **Auth:** none (read-only).

### `stream_count`

```rust
pub fn stream_count(env: Env) -> u32
```

Returns the number of streams ever registered.

- **Auth:** none (read-only).
- **Errors:** none documented.

### `get_streams_page`

```rust
pub fn get_streams_page(env: Env, offset: u32, limit: u32) -> Vec<u64>
```

Returns a registration-ordered page of stream ids. `limit` is capped at
`MAX_PAGE_SIZE` (50); an `offset` past the end returns an empty vec. Prefer
this over [`get_all_streams`](#get_all_streams) on a large registry.

- **Auth:** none (read-only).
- **Errors:** none documented.

### `get_stream_record`

```rust
pub fn get_stream_record(env: Env, stream_id: u64) -> Result<StreamRecord, RegistryError>
```

Read-only accessor for a single stream's registry-side summary: sender,
recipient, token, amount, withdrawn and status.

- **Auth:** none (read-only).
- **Errors:** `StreamNotFound` if no stream with that id is registered.

### `get_admin`

```rust
pub fn get_admin(env: Env) -> Result<Address, RegistryError>
```

Returns the admin address recorded at `initialize`.

- **Auth:** none (read-only).
- **Errors:** `NotInitialized` if called before `initialize`.

### `get_stats`

```rust
pub fn get_stats(env: Env) -> RegistryStats
```

Returns the current `RegistryStats`. The Registry keeps these as incremental
counters, so this is a single read: its cost does not grow with the number of
streams. `total_streamed` is the lifetime cumulative committed amount, not live
accrual.

- **Auth:** none (read-only).

### `get_active_streams`

```rust
pub fn get_active_streams(env: Env) -> Vec<u64>
```

Returns the ids of every stream whose last-recorded status is `Active`.

- **Auth:** none (read-only).

## Events emitted

The Registry emits a typed event each time it changes its index, defined in its
`events.rs`. Each event's name is its first topic `Symbol`, and `stream_id` is
the second topic:

| Event | Topics | Data |
|---|---|---|
| `register` | `[Symbol("register"), U64(stream_id)]` | `I128(amount)` |
| `update` | `[Symbol("update"), U64(stream_id)]` | `I128(withdrawn)` |

These are single-value events: the data is the amount itself, not a `Vec`. The
Stream contract's `create`/`withdraw`/`cancel` events remain the lifecycle feed
that `stellar-stream-hive-api` indexes; the API does not need the Registry's
events. The consolidated table lives in
[Stream contract: events emitted](/docs/contracts/stream#events-emitted).

## Security notes

- `register_stream` and `update_stream` take no caller and are intentionally
  open: anyone can call them. The Registry never holds or moves funds, so the
  worst a third party can do is corrupt its statistics and listings. Funds
  safety depends entirely on the Vault's caller check (see
  [Security Model](/docs/concepts/security-model)). See the contract repo's
  [`docs/registry.md`](https://github.com/Stellar-Hive/stellar-stream-hive-contract/blob/main/docs/registry.md) for the rationale.
- Because of that lower stakes profile, the Registry is a reasonable place to
  add caching, pagination, or alternate indexing strategies over time without
  touching the fund-safety-critical parts of the platform.

<CalloutBox variant="warning" title="Registry data is not a source of truth">
  Because anyone can write to the Registry, its stats and stream listings can
  be polluted by third parties. Do not treat Registry data as authoritative;
  verify against the Stream contract.
</CalloutBox>
