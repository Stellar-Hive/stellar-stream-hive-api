# Web App Guide

The web app ([`stellar-stream-hive-frontend`](https://github.com/Stellar-Hive/stellar-stream-hive-frontend))
is the point-and-click way to use Stellar Stream Hive without touching the CLI
or writing any code. This guide walks through the full lifecycle of a stream
from the web app's perspective. Everything here is a thin UI over the same
contract calls documented in [Contract References](/docs/contracts/stream) and
the same data served by the [indexer API](/docs/api/overview) -- nothing the
web app does is privileged or otherwise unavailable to you directly.

## Connecting Freighter

1. Install the [Freighter](https://www.freighter.app/) browser extension and
   create or import an account.
2. In Freighter's network selector, choose **Test Net** to match the web
   app's default network (see [Network Guide](/docs/getting-started#network-guide)
   if you need to point it at a different network).
3. On the web app, click **Connect Wallet**. Freighter will prompt you to
   approve the connection -- approving only shares your public address with
   the site; it never shares your secret key, and no transaction is signed at
   this step.
4. Once connected, the app displays your shortened address and the active
   network badge in the header (it does not display a wallet XLM balance).

## Creating a stream

1. Click **Create Stream** in the navigation bar.
2. Fill in the form:
   - **Recipient** -- the `G...` address that will receive the stream.
   - **Token** -- defaults to native XLM; can be set to any SEP-41 token
     contract address.
   - **Amount** -- the total amount to lock, in the token's display units
     (the app converts to the token's smallest unit, e.g. stroops for XLM,
     under the hood).
   - **Start** and **End** -- pick calendar dates/times; the app converts
     these to ledger sequence numbers internally by estimating from the
     current ledger and Stellar's ~5-second ledger close time (see
     [Converting dates to ledgers](/docs/concepts/streaming-math#converting-dates-to-ledgers)).
   - **Cliff** (optional) -- a date before which nothing is withdrawable, even
     though accrual has started. Leave blank for no cliff.
   - **Cancellable** -- whether you (the sender) can cancel this stream
     later. This cannot be changed after creation.
3. Click **Create Stream**. Freighter will prompt you to sign the
   `create_stream` transaction. This is the only signature required to fund
   the entire stream -- no separate token approval (`approve`) transaction is
   signed; instead, `create_stream` invokes the [Vault contract's `deposit`](/docs/contracts/vault#deposit)
   in the same transaction, and your single signature authorizes both the
   contract call and the token transfer into the Vault via Soroban's sub-invocation
   auth (`sender.require_auth()`).
4. Once confirmed, the new stream appears on your dashboard with one of the
   statuses shown by the app's status badge: **Scheduled** (its start time is
   still in the future), **Active** (accruing), **Cliff pending** (accruing,
   but nothing is withdrawable until the cliff ledger is reached),
   **Completed**, or **Cancelled**.

### Custom token detection

When you enter a token contract address, the app reads the token's `symbol()`
and `decimals()` from the contract to display a friendly token name and to
convert your amount into the token's smallest unit. If the contract does not
expose those functions (or the call fails), the app falls back to manual
entry: you supply the symbol and decimals yourself, and the form shows a
warning that the values could not be auto-detected. Double-check the decimals
you enter in that case -- the app trusts them for the conversion.

<CalloutBox variant="warning" title="Wrong decimals change how much is deposited">
  The **Amount** you type is multiplied by `10^decimals` to produce the raw
  integer the contract stores. If the decimals value is wrong, the deposited
  amount is off by that factor: too few decimals under-deposits (e.g. entering
  `1` with `decimals = 0` locks one whole unit instead of a fraction), and too
  many over-deposits by the same factor. Confirm the token's decimals before
  signing, especially when the app could not detect them automatically.
</CalloutBox>

<CalloutBox variant="warning" title="Dates are estimates, ledgers are exact">
  The **Start**, **End**, and **Cliff** dates are converted to ledgers using
  roughly 5 seconds per ledger. Real ledger close times vary, so the date you
  picked and the moment the stream actually starts or ends can differ. The
  on-chain schedule is the ledger numbers, not the calendar dates.
</CalloutBox>

## Your streams

Two pages list the streams tied to your connected wallet:

- **Sending** (`/sending`) -- streams you created as the sender.
- **Receiving** (`/receiving`) -- streams where you are the recipient.

Each list can be narrowed with status filters and exported to CSV for
record-keeping or spreadsheet analysis.

<CalloutBox variant="info" title="These lists need the indexer API">
  The **Sending** and **Receiving** pages read from the
  [indexer API](/docs/api/overview), configured via the
  `NEXT_PUBLIC_API_BASE_URL` environment variable. If that variable is unset
  or the API is unreachable, these lists will be empty or fail to load even
  though the streams exist on-chain.
</CalloutBox>

## Watching a balance accrue

Open any stream's detail page to see a live-updating progress bar and two
figures:

- **Streamed** -- the total vested so far (`streamed_amount`).
- **Withdrawable** -- what the recipient could withdraw right now
  (`withdrawable_amount`).

<Figure
  src="/web-app-balance.png"
  alt="A stream detail page showing the live progress bar with Streamed and Withdrawable figures."
  caption="A stream's detail page: the progress bar and the live Streamed and Withdrawable figures update once per second."
/>

Rather than polling the indexer API on every tick, the web app computes the
live balance client-side in `useLiveBalance`: it fetches the latest ledger
sequence and close timestamp from the network, ticks once per second by
estimating the current ledger from elapsed wall-clock time (~5 seconds per
ledger), and re-syncs with the chain every 30 seconds to correct for drift in
actual ledger close times. All amount math uses `BigInt` floor division with
the exact multiply-before-divide formula in
[Streaming Math](/docs/concepts/streaming-math) -- the web app never
overstates what the contract itself would allow you to withdraw.

<CalloutBox variant="warning" title="Before the cliff, Withdrawable stays at zero">
  If a stream has a cliff, expect **Streamed** to climb from the moment the
  page loads (once `start_ledger` has passed) while **Withdrawable** stays
  pinned at `0` until `cliff_ledger` is reached, at which point it jumps to
  match everything accrued since `start_ledger`. This is expected --
  see [Cliff behavior](/docs/concepts/streaming-math#cliff-behavior).
</CalloutBox>

## Withdrawing

From a stream's detail page, the recipient sees a **Withdraw** button:

1. Click **Withdraw** and choose **Max withdrawable** (the default) or enter a
   **Custom amount**, then click **Confirm withdrawal**. Rather than trusting
   the client-side ticking estimate or calling `withdraw_max`, the app
   re-fetches `withdrawable_amount` directly from the contract on-chain at
   submit time (validating that any custom amount does not exceed it) and calls
   [`withdraw`](/docs/contracts/stream#withdraw) with that exact re-fetched
   (or requested) amount.
2. Freighter prompts you to sign. Only the connected wallet's address needs to
   match the stream's `recipient` -- the contract enforces this itself (see
   [Stream contract: withdraw](/docs/contracts/stream#withdraw)), so
   attempting to withdraw from an account that isn't the recipient will be
   rejected by the contract, not silently allowed by the UI.
3. Once confirmed, the withdrawn amount lands in your wallet immediately, and
   **Withdrawable** resets toward `0` (climbing again as more time passes).

## Cancelling a stream

Only visible to the sender, and only when the stream was created with
**Cancellable** set to true:

1. From the stream's detail page, click **Cancel Stream**.
2. The app shows a confirmation with the exact split that will occur --
   how much the recipient will keep (everything streamed so far) and how much
   will be refunded back to you -- computed via
   [Streaming Math: what happens on cancel](/docs/concepts/streaming-math#what-happens-on-cancel).
   If you cancel **before `start_ledger` or before `cliff_ledger`**, the
   streamed amount at cancellation is `0`: the recipient receives `0` and the
   entire `total_amount` (100% of the locked funds) is refunded to the sender.
3. Confirm and sign with Freighter. Once the transaction lands, the stream's
   status badge changes to **Cancelled**, the recipient's already-accrued portion
   (if any had vested past the cliff) becomes immediately withdrawable, and the
   remainder is refunded to you in the same transaction.

<CalloutBox variant="danger" title="Cancellation is immediate and irreversible">
  There is no "undo cancel." Once confirmed, the stream stops accruing
  permanently at that ledger. If you're unsure, double-check the amounts
  shown in the confirmation dialog before signing.
</CalloutBox>

## Troubleshooting

### "Wrong network" badge

**Symptom:** the app shows a **Wrong network** badge (often next to your
connected address) and actions like creating or withdrawing a stream are
disabled or fail.

**Cause:** Freighter is set to a different network than the one the web app
is configured for. The app compares the wallet's active network against its
own configuration and warns when they don't match.

**Fix:** open Freighter's network selector and switch to the network that
matches the app's configuration (by default, **Test Net**). The badge clears
once the two agree. If you intentionally need a different network, see the
network table in the [Network Guide](/docs/getting-started#network-guide) to
confirm which network the app is pointed at.
